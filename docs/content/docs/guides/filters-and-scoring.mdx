description: 正确组合 area、paper type、spotlight、search depth 和 min score。

过滤用于表达明确约束，不应代替 query 本身。推荐先检索，再用 `list_paper_areas` 确认可用值。

## 过滤器

| 参数 | 何时使用 | 注意点 |
|---|---|---|
| `area` | 已知研究领域 | 必须使用语料中的精确值 |
| `paper_type` | 区分论文类型 | 值来自当前静态快照 |
| `spotlight_only` | 只看 spotlight | 可能显著缩小候选集 |
| `min_score` | 去掉排名尾部 | 只适合当前 query 粗过滤 |

Dense 与 BM25 在召回阶段使用相同过滤语义，`min_score` 在融合后应用。

## `top_k` 与 `search_depth`

`top_k` 控制最多返回多少篇新论文；`search_depth` 控制融合候选窗口。Session 已见论文只从窗口中移除，所以二者解决不同问题。

```text
top_k=5, search_depth=20
候选窗口 20 篇 -> 移除 session seen -> 最多返回 5 篇
```

增大 depth 会增加本地检索和去重工作，但不会让 query 重新生成多次 embedding。不要无条件设为全局上限；先观察 `truncated` 和空轮提示。

## `min_score` 的正确用法

因为 score 来自 weighted RRF，它只编码两路排名位置。适合用法：

- 在同一个 query 的结果内排序。
- 用保守阈值去掉明显靠后的候选。
- 对比是否调整当前 query 的窗口。

不适合用法：

- 把 `0.8` 解释为 80% 相关概率。
- 用固定阈值比较不同 query 的质量。
- 把 score 当成论文质量、录用等级或引用影响力。

## 调试过滤

当结果意外为空，依次移除 `min_score`、spotlight、paper type、area，再检查 session 是否已经看过候选。必要时用无 session 的相同 query 判断是检索问题还是去重结果。
