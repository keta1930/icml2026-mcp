title: HTTP 与健康检查
description: Streamable HTTP MCP 路径、liveness、readiness 与响应语义。
---

服务在同一 ASGI 应用中暴露 MCP 和两个普通 HTTP 健康路由。

| 路径 | 方法 | 用途 |
|---|---|---|
| `/mcp` | MCP transport | Streamable HTTP 初始化、tools/list 与 tools/call |
| `/health/live` | GET | 进程是否存活 |
| `/health/ready` | GET | 本地 state/index 是否可服务 |

## Liveness

```bash
curl -fsS http://127.0.0.1:20441/health/live
```

成功返回 HTTP 200：

```json
{ "status": "ok" }
```

它不检查索引、SQLite、provider 或 key。

## Readiness

```bash
curl -fsS http://127.0.0.1:20441/health/ready
```

Ready 返回 HTTP 200 和 `{"status":"ready"}`；失败返回 HTTP 503 和 `{"status":"not_ready"}`。

Readiness 会检查 runtime SQLite、原始语料、current manifest、Chroma collection/ID/维度和 FTS5 一致性，但不读取 DashScope key、不调用 provider。

## 监控建议

- 进程管理器使用 liveness 判断是否需要重启。
- 负载入口使用 readiness 判断是否接收流量。
- 不要因为 provider 暂时不可用把本地索引标记为 not ready。
- 容器启动期允许 runtime index 复制和完整验证，配置合理的 `start_period`。

公网代理探测需要发送被应用允许的 Host；否则 DNS rebinding 防护会拒绝请求。
